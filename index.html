F2FS Flash Storage Simulator

In-Place Updates vs. Log-Structured Writes

Flash memory (SSDs, smartphones, USB storage) has an unavoidable physical rule: a page cannot be overwritten directly once written—an entire block/segment must be erased first. Traditional in-place updates trigger destructive full-segment erases and rewrites, causing severe write amplification (WAF ~63x) and burning through drive lifespan.

This simulator models flash hardware at the page and segment level to demonstrate how F2FS (Flash-Friendly File System) solves this bottleneck using out-of-place sequential appends, logical-to-physical mapping tables, and greedy garbage collection—slashing write amplification down to 1.74x and delivering a 36x reduction in flash wear.

01

Out-of-Place Writes

Because NAND flash cannot overwrite without an erase, F2FS writes updates to clean pages and marks old versions invalid, avoiding destructive full-segment rewrites.

02

Greedy Garbage Collection

When clean space drops, the cleaner selects segments containing the fewest valid pages, migrating surviving data and restoring completely free segments to the pool.

03

80/20 Workload Skew

Hot data blocks invalidate rapidly in the same segments. This clusters invalid space together, allowing the garbage collector to reclaim space with 13% fewer page migrations.
